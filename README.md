# daily-patrol · 每日巡查技能

把代码库的「每日巡查/例行体检」做成一个可复用的 Agent 技能：结构化的健康巡检流程 + 一套从真实项目日常巡查中打磨出来的**红三分诊协议**。

巡查的价值不在跑命令——构建和测试谁都会跑——而在分诊：**每一个红，先证明它是真的，再判断它是谁的，最后才决定动不动手。** 巡查最大的成本不是没发现问题，而是把假红当真债修。

## 它解决什么问题

一个仓库被多个会话/多人并行开发时，周期性体检会反复撞上同一批坑：

- 共享工作树上有并行会话的未提交改动，体检红到底是不是回归？
- 测试全量两跑红数不一致（今天 13 个文件、明天 16 个），哪些是真红？
- 上期归档过的债，这期要不要重查？
- 扫描器报了 26 个「死代码」，敢不敢直接删？

本技能把这些问题沉淀成固定协议：**先定性现场 → 对账 → 分级体检 → 红三分诊 → 修复纪律 → 诚实报告**，并附带一份判例手册（每条判例都来自真实翻车/翻案）。

## 流程一览

```
① 定性现场    这棵树是哪棵树？工作树==基线吗？M 态≠在制（双证据定性）
② 对账        读上期报告与归档清单（免重查）；审计面=增量
③ 分级体检    T1 快门禁 → T2 全量测试（两跑）→ T3 部署/产物 → T4 专项扫描
④ 红三分诊    它是真的吗？它是谁的（五桶）？要不要现在修？
⑤ 修复纪律    完整链先行/同链排查/测试进闸；噪声源驱动，不为洁癖翻热文件
⑥ 报告归档    结果表+分诊表+判例入库+判缓/判不做好理由；负发现也是产出
```

分诊五桶：**在制不代管 / 他方已落库债 / 我方回归 / flake / 陈旧测试**。

## 判例速览

> 完整语境见 [references/triage.md](references/triage.md)

- **体检红先验工作树==origin，再定回归**——树上不是正典基线时，红与绿都不携带关于代码库的信息。
- **两跑红数波动以文件级并集为准**——红数绝对值不携带定性信息，文件级并集才携带。
- **「跑过」≠「提交的版本跑过」**——工具入库前必须以入库形态烟测一次。
- **gate 绿 ≠ 浏览器绿**——解析器容忍不等于运行时正确。
- **红=三种病**（测试错/产品错/断言陈旧），定性错了会把好代码改坏。
- **存量形态挂两次就该重估**——挂起是当时不划算，不是永远不划算。
- **自愈意味着归档清单会过期**——「连续多轮红」的旧账值得定期重查。

## 安装

需要支持 SKILL.md 技能规范的 Agent 环境（ZCode 等）。

```bash
# 用户级（全局可用）
git clone https://github.com/sun-zihang/daily-patrol.git ~/.agents/skills/daily-patrol

# 或项目级（仅本仓库可用）
git clone https://github.com/sun-zihang/daily-patrol.git .agents/skills/daily-patrol
```

装好后对 Agent 说「跑一轮每日巡查 / 做一次例行体检」即可触发；也可以直接引用：

```
/daily-patrol 对当前仓库做一次例行体检
```
