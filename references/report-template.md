# 巡查报告模板

报告是巡查的正式产出物：它同时服务三个读者——下一期巡查的你（对账）、并行协作的会话（避免重复排查）、以及未来的自己（判例复利）。落到仓库的固定位置（如 `docs/巡查轮N报告-YYYY-MM-DD.md`）。

```markdown
# 巡查轮 N 报告：<一句话主题>

> 日期 · 触发方式（定时/事件触发/手动）· 代码变更笔数（若有）

## 一、体检形态

本轮用什么形态跑的：共享树还是隔离 worktree、基线 commit、
与上期形态的差异及原因（一段话说清，让下期可以直接复用或改进）。

## 二、结果

| 项 | 结果 |
| --- | --- |
| T1 快门禁 | 构建 Xs PASS / lint / format |
| T2 全量测试（两跑） | 一跑 X 文件红 / 二跑 Y 文件红 / 并集 Z 文件 |
| T3 部署与产物 | 线上特征核验 N/N / 镜像一致性 |
| T4 专项扫描 | 扫描器 × 结果 |

**总判定**：零回归 / 回归 M 件（清单）/ 待分诊 K 件。

分诊表（每个红一行）：

| 红 | 定性 | 证据 | 处置 |
| --- | --- | --- | --- |
| <文件/用例> | flake | 单跑绿+并批绿 | 留观察（触发条件：并集稳定 ≥3 轮） |
| <文件/用例> | 他方债 | 最后落点 <commit>，零触碰 | 归档 <域> 清单 |
| <文件/用例> | 我方回归 | 本工作流 commit 引入 | 本轮修复（见第三节） |

## 三、清偿内容

本轮实际修复/接线/清偿的内容。每件写：缺口是什么（对账发现的，
不是猜的）→ 修了什么 → 同链入口排查结果 → 测试与门禁。

## 四、判例

本轮新学到的判断规则，格式：**判例一句话（加粗）** + 为什么 + 怎么应用。
翻车教训优先入库（第一版误判了什么、被什么信号纠正的）。

## 五、余注

- 判缓：<项> — 理由 — 复检触发条件
- 判不做：<项> — 理由（永久性的，如红线/成本超收益）
- 观察项：<项> — 触发条件
- 负发现：检查过 X 没有问题（如实记录，防下期重查）
- 基线更新：归档清单的增删
```

## 写作纪律

1. **结论先行**：总判定放在第二节第一眼位置，「零回归」和「回归 M 件」是读者最想知道的事。
2. **定性必附证据**：分诊表每一行都要有可复核的证据（commit 号、单跑结果、diff 事实），不写「应该是 flake」这种无证据判语。
3. **数字对账**：报告里的计数（几文件/几用例/几笔）与原始输出对得上，摘要不冒充覆盖面。
4. **判缓/判不做分开记**：判缓是「现在不做，条件触发再做」；判不做是「明确不做，理由成立期内不再议」。混在一起等于都没记。
5. **报告本身也是被巡查对象**：下一期对账从读上一期报告开始，所以报告要能独立读懂（不依赖当天的会话记忆）。
